What this is — and what it isn't

You asked for the last employee you'll ever need. Here's the honest version of that, so you build on solid ground instead of hype.

What Jarvis genuinely becomes

  • A single orchestration layer over Claude Code, your files, calendar, email, and Summit OS.
  • Reachable three ways — desk voice, phone text, and a real inbound phone call.
  • An executor — it starts builds, drafts proposals, scrapes leads, checks build status, schedules events, writes to your vault.
  • Persistent — it remembers across sessions through your Obsidian vault + a memory engine.

Where to stay clear-eyed

  • I can't install it on your PC from here. I'm sandboxed. This guide + the CLAUDE.md blueprint is what Claude Code on your Windows box executes.
  • It is not fully autonomous. Anything that spends money or sends outreach keeps you in the loop — by design, not limitation.
  • "Call from anywhere" = Twilio. Telegram/Happy give phone control & texting; a real dial-in number is Twilio Voice.
  • No repo named "grapify" exists. You're thinking of gitingest / repomix. Both are in the catalog below.
The build strategy: this is staged on purpose. Trying to wire voice + phone + overlay + 40 skills + Summit OS in one sitting is exactly the QualifyOS failure mode — conflating distinct products into one launch. We ship the simplest working Jarvis first, then bolt on channels. Stage 1 is doable this weekend.

Stage 1 · Windows foundation

Get the machine ready

Your uploaded guide was Mac-only (it's from ethanplusai/jarvis). This is the Windows-native path — PowerShell, VS Code, Claude Code. No WSL required, though it's an option.

  1. Install Node.js LTS from nodejs.org (gives you npm). Then in PowerShell confirm: node -v
  2. Install Python 3.12+ from python.org — check "Add to PATH" during install. Confirm: python --version
  3. Install VS Code + the "Claude Code" and "Python" extensions.
  4. Install Claude Code: npm install -g @anthropic-ai/claude-code then run claude once to sign in.
  5. Install Codex (your second engine) per its CLI docs, so Jarvis can route heavy coding either way.
  6. Install Obsidian from obsidian.md. Create a vault at C:\Users\DanGi\JarvisVault — this becomes Jarvis's long-term memory.
  7. Create the project folder: mkdir C:\Users\DanGi\Jarvis and drop the CLAUDE.md blueprint (below) inside it.
  8. Run Claude Code in that folder: cd C:\Users\DanGi\Jarvis then claude. It reads CLAUDE.md and builds the whole project.
PowerShell tip: if global npm installs error on permissions, run PowerShell as admin once, or set a user npm prefix: npm config set prefix "$env:APPDATA\npm". Windows Defender may prompt on the Electron overlay's always-on-top window — allow it.

Ideas
The memory layer

Obsidian as Jarvis's brain-on-disk

Your vault is the source of truth — human-readable, versionable, yours forever. A memory engine sits on top for fast recall. This is how Jarvis remembers "the deploy is Friday" three weeks later.

Vault access — pick one

  • Filesystem (simplest): the vault is just a markdown folder. Claude Code + Desktop Commander already read/write it directly. Zero setup.
  • StevenStavrakis/obsidian-mcp: npx, direct filesystem, structured note tools. No plugin needed.
  • MarkusPfundstein/mcp-obsidian: the most-used server. Needs the Obsidian "Local REST API" plugin + key. Richest tools (search, patch, daily notes).
Recommendation: start Filesystem for Stage 1, upgrade to mcp-obsidian in Stage 5 when you want structured search.

Recall engine — on top of the vault

  • mem0: cross-session memory layer. Structured "remember this fact" recall. The standard pick.
  • supermemory: fast local memory engine, runs fully local. Good privacy-first alternative.
  • Your existing Supabase: can back a memory table too, with your RLS pattern.
Vault structure to seed: /Jarvis/identity.md, /Jarvis/rules.md, /Jarvis/memory/, /Summit/clients.md, /Summit/playbook.md. Everything from your 18 screenshots + Sales Playbook goes into /Jarvis/knowledge/.

The Windows CLAUDE.md blueprint

# CLAUDE.md — PROJECT JARVIS (Windows)

## Identity
You are JARVIS — Dan's personal AI operator. Calm, dry British wit, decisive.
Address him as "sir" sparingly. Short answers by default; detail on request.
Persona persists regardless of underlying model.

## Mission
Be reachable at the desk (voice), by text (Telegram/SMS), and by phone (Twilio).
Read files, calendar, email, and Summit OS state. Start and monitor builds.
Draft proposals, sites, PDFs. Remember everything via the Obsidian vault.

## Build this project (Windows-native)
1. backend/  — Python FastAPI. Reuse Dan's Railway patterns.
   - /brain    Claude tool-calling loop (Sonnet reason, Haiku for structured tasks)
   - /voice    Groq Whisper STT (free) + ElevenLabs TTS (British voice)
   - /phone    Twilio ConversationRelay webhook (/twiml, /ws) → brain
   - /sms      Telegram bot + optional Twilio SMS webhook → brain
   - /memory   Obsidian vault read/write + mem0 recall
2. overlay/  — Electron, transparent, frameless, always-on-top (bottom-right).
   - Three.js particle orb; state color: idle=cyan, thinking=amber,
     listening=green, error=red. Orb amplitude reacts to TTS audio.
   - WebSocket to backend for live state + transcript.
3. mcp/      — wire these MCP servers:
   - obsidian (vault), desktop-commander (files/terminal), serena (code),
     playwright (browser), chrome-devtools (QA), context7 (docs), sentry (errors)
4. summit/   — tools hitting Dan's Railway endpoints:
   - GET  /clients, /agents/status, /analytics/activity-feed   (auto-run)
   - POST /dispatch, demo-build, scrape, proposal            (CONFIRM first)

## Hard rules
- NEVER send email/SMS, spend credits, post publicly, or run destructive
  commands without showing a preview and getting an explicit "yes".
- NEVER expose API keys in frontend. Keys live in backend .env / Railway env.
- Prefer static outputs + confirmation over silent autonomy.
- Log every action to /Jarvis/memory/ in the vault.
